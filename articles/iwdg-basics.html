独立看门狗：程序跑飞时的最后保障

从“定时必须报到”的生活比喻开始，理解 IWDG 的独立时钟、递减计数、超时计算和工程使用方法。

📅 2026-08-04🐑 小羊半夏⏱ 计算中
#STM32#IWDG#可靠性

一、为什么需要看门狗

单片机可能因为程序死循环、指针异常、通信等待、强电磁干扰或意外状态而无法继续完成正常任务。此时系统表面上仍然通电，但控制逻辑可能已经停止。

可以把看门狗理解成一个定时点名器：程序必须在规定时间内“报到”，否则看门狗就认为系统失去控制，并触发复位。

看门狗不能修复程序中的缺陷，但可以在缺陷或干扰出现后，让设备自动恢复到可重新启动的状态。

二、IWDG 为什么叫“独立”看门狗

IWDG 通常由独立低速内部时钟 LSI 驱动。即使主时钟、PLL 或主程序出现问题，只要独立时钟仍在工作，看门狗计数就会继续进行。

这种独立性使 IWDG 更适合承担系统最后一道恢复保障，但也意味着它的时钟精度通常不高，实际超时时间可能与理论值存在偏差。

重要：LSI 的标称频率和误差范围因具体 STM32 系列而异。正式设计时应查看对应芯片的数据手册，而不是把示例频率直接用于所有型号。

三、IWDG 的内部工作过程

  1. LSI 时钟经过预分频器降频。
  2. 重装载寄存器的数值装入递减计数器。
  3. 计数器按照分频后的时钟不断减小。
  4. 程序正常运行时，定期执行刷新操作，把计数器重新装满。
  5. 如果计数器减到零仍未刷新，系统产生复位。

四、超时时间怎样计算

常见近似计算方式如下：

超时时间 ≈ (重装载值 + 1) × 预分频系数 ÷ LSI 频率

假设某型号 LSI 按 40 kHz 估算，预分频系数为 32，重装载值为 500：

(500 + 1) × 32 ÷ 40000 ≈ 0.4008 s

也就是理论超时约 400 ms。由于 LSI 本身有偏差，真实时间可能更短或更长，因此不能把看门狗时间设计得刚好等于任务的最长执行时间。

设计余量怎么留

应先测量或估算正常程序最坏情况下需要多久才能走到刷新点，再结合时钟误差、通信阻塞、Flash 操作和中断占用预留足够余量。

五、STM32 配置流程

不同系列和库版本的函数名称会有差异，但整体顺序通常是：

  1. 允许写入 IWDG 配置寄存器。
  2. 设置预分频值。
  3. 设置重装载值。
  4. 把重装载值装入计数器。
  5. 启动独立看门狗。
// 标准外设库风格的示意代码
void IWDG_Init(void)
{
    IWDG_WriteAccessCmd(IWDG_WriteAccess_Enable);
    IWDG_SetPrescaler(IWDG_Prescaler_32);
    IWDG_SetReload(500);
    IWDG_ReloadCounter();
    IWDG_Enable();
}

示例仅用于说明顺序，具体函数和参数需要结合所用 STM32 系列、库版本和芯片手册核对。

六、什么叫“喂狗”

喂狗就是在计数器尚未减到零之前执行刷新，让它重新从重装载值开始计数。

void IWDG_Feed(void)
{
    IWDG_ReloadCounter();
}

关键不在于“频繁刷新”，而在于“只有确认系统关键任务正常时才刷新”。

七、喂狗应该放在哪里

最简单的程序可以在主循环完成一轮关键工作后刷新。使用实时操作系统时，可以让各关键任务上报运行状态，再由专门的监控任务统一判断是否允许刷新。

// 伪代码：所有关键任务都正常才允许刷新
if (sensor_ok && control_ok && communication_ok) {
    IWDG_Feed();
}
核心原则：喂狗点应代表“系统整体仍然健康”，而不是仅仅代表某一行代码仍能执行。

八、常见错误

1. 在定时中断中无条件喂狗

即使主循环或关键任务已经死锁，只要定时中断仍运行，看门狗就永远不会超时，失去监控意义。

2. 在多个位置随意喂狗

任何一个非关键路径都可能持续刷新计数器，从而掩盖其他模块的故障。

3. 超时时间设置太短

Flash 擦写、通信等待、复杂计算或启动初始化都可能偶尔超过设定时间，引起正常程序被误复位。

4. 超时时间设置太长

系统发生故障后需要很久才恢复，可能无法满足设备的安全或连续运行要求。

5. 只复位，不记录原因

设备会不断自动恢复，但开发者不知道为什么复位。建议在启动阶段读取复位标志，并通过日志或非易失性存储记录异常次数。

九、调试阶段怎样处理

开启 IWDG 后，部分芯片无法通过普通软件方式停止，调试断点可能导致计数器超时并复位。应查看芯片是否支持在调试暂停时冻结 IWDG，或者在开发阶段使用更长超时时间。

  • 确认调试器暂停时 IWDG 是否继续计数。
  • 启动代码中读取并清除复位来源标志。
  • 测试故意停止喂狗后是否能够复位。
  • 测试正常最长任务不会误触发复位。
  • 测试连续复位时是否存在安全输出状态。

十、看门狗之外还需要什么

可靠系统不能只依赖 IWDG。还应包括输入限幅、通信超时、状态机异常恢复、电源监控、棕断复位、错误日志和安全输出设计。

学习总结：看门狗不是“程序不会出错”的证明，而是承认系统可能出错后，为恢复能力增加的一层保障。
