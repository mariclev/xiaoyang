Codex 安装与第一次使用

从安装 CLI、登录账号、打开代码仓库，到完成第一次“先理解、再修改、后验证”的 AI 辅助开发流程。

📅 2026-08-04🐑 小羊半夏⏱ 计算中
#Codex#AI工具#Git

一、Codex 是什么

Codex 可以在终端、编辑器或应用中协助理解代码、修改文件、运行命令和检查结果。对初学者来说，它最大的价值不是“替你写完所有代码”，而是帮助你更快看懂项目结构、定位问题和形成可执行的修改步骤。

更好的使用方式是把 Codex 当作一名会阅读仓库、会提出方案、但仍需要你验收的开发协作者。

二、安装 Codex CLI

使用 npm 安装 CLI 的官方命令如下。安装前应先确认电脑已经能够正常使用 Node.js 和 npm。

npm i -g @openai/codex

安装完成后检查命令是否可用：

codex --version
更新提示：工具会持续迭代，遇到界面或命令差异时，应优先查看 OpenAI 官方 Codex 页面和帮助文档。

三、登录账号

在终端输入 codex 后，可以按照界面提示使用 ChatGPT 账号登录，也可以按组织要求采用其他认证方式。首次使用时，先完成登录，再选择要操作的本地文件夹或 Git 仓库。

codex

登录完成后，进入项目根目录再启动 Codex，可以减少它读取到无关文件的概率。

cd your-project
codex

四、第一次任务不要直接让它大改

首次接触一个工程时，建议先让 Codex只读分析，而不是马上改代码。一个比较稳妥的起始提示是：

请先阅读这个仓库，不要修改文件。
说明项目目录结构、入口文件、主要模块、构建方法，
并列出你目前无法确认的问题。

这样可以先判断它是否真正理解项目，再决定后续修改范围。

五、描述任务时要包含四类信息

  1. 目标：最终要实现什么。
  2. 范围：允许修改哪些文件，哪些不能动。
  3. 限制：芯片、编译器、接口、代码风格或兼容性要求。
  4. 验收：怎样才算完成，例如能编译、测试通过或页面达到指定效果。
示例：“只修改显示模块，不改通信协议；保持现有函数接口；完成后说明改动文件，并检查是否存在编译错误。”

六、让 Codex 工作时保留 Git 保护

修改前先确认项目处于 Git 仓库中，并查看当前状态。这样即使结果不理想，也能清楚看到改动或恢复文件。

git status
git switch -c codex-test

建议把较大的任务放在新分支完成。每完成一个可验证的小步骤，再提交一次，而不是一次生成大量难以审查的变化。

七、正确的验收流程

  • 先查看它修改了哪些文件。
  • 阅读关键差异，不只看最终说明。
  • 运行编译、测试或静态检查。
  • 检查异常路径、边界条件和硬件相关假设。
  • 确认没有把密钥、密码或私人数据写入仓库。

八、适合交给 Codex 的任务

  • 解释陌生代码和函数调用关系。
  • 整理重复代码、补充错误处理。
  • 生成测试、文档和基础页面。
  • 根据编译错误定位可能原因。
  • 在明确限制下完成小范围功能修改。

涉及电源控制、硬件保护、通信安全和关键算法时，仍应由开发者结合原理图、数据手册与实测结果进行确认。
